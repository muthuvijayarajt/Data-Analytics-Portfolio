# Banking & Fraud Analysis (SQL)

## Overview
This project analyzes a realistic banking database to extract insights related to
customer behavior, account activity, transactions, and fraud monitoring using SQL.

The analysis simulates real-world banking and compliance scenarios such as
KYC verification, fraud alert tracking, credit utilization, and risk analysis.

## Dataset
- Total size: ~80,000 records
- Database type: Relational (10 tables)
- Domain: Banking & Financial Services

### Tables Included
- Customers
- Accounts
- Transactions
- Fraud_Alerts
- Credit_Cards
- Loans
- KYC_Documents
- Staff
- Branches
- Customer_Feedback

## Objectives
- Analyze customer and account-level activity
- Identify suspicious and high-risk transactions
- Track fraud alerts and resolution status
- Evaluate loan and credit card usage patterns
- Support compliance and KYC validation analysis
- Perform branch-wise and customer-level insights

## SQL Skills Used
- Joins (INNER, LEFT)
- Subqueries
- Common Table Expressions (CTEs)
- Window Functions
- Aggregations
- Date-based analysis
- Filtering and data validation

## Key Analysis Performed
- Active vs inactive account analysis
- High-value and suspicious transaction detection
- Customer risk profiling using transaction and balance data
- Fraud alert severity and resolution analysis
- Credit card utilization and loan repayment analysis
- Branch-level and staff-level performance insights
- Customer feedback sentiment overview

## Files
- `banking_dataset.sql` – Banking database with ~80k records
- `banking_queries.sql` – 40–50 SQL queries covering analytical and fraud use cases

## Highlights
- Worked with a multi-table relational banking schema
- Wrote 40–50 SQL queries simulating real-world banking scenarios
- Focused on fraud detection, compliance, and risk analysis
- Used advanced SQL concepts for business-driven insights
